# smodel

Open `/smodel` to pick a Claude, Codex, or agy model and continue the current Claude Code conversation in a separate side chat. Choose a model, type a message, and press Enter. The first message sends conversation context to that provider; a dim notice appears above the input. Use **Back to models** to switch chats or **Close** to dismiss the pane. Surfaces without an input component, including mobile, show a read-only chat.

## In the pane

- **Open it while Claude is still working.** `/smodel` is registered as an immediate command, so typing it during a running turn opens the pane at once instead of waiting for the turn to end. Press `ctrl+x tab` (or click the pane) to move the keyboard into the pane and type there while the main chat keeps thinking.
- **Numbers the CLIs report.** Under the chat title a dim block shows the last turn's tokens in, cache counts, tokens out, thinking tokens and duration; the tokens sent (and the share of the context window when the CLI reports one); Claude's cost when its CLI reports one, labelled as a list-price equivalent and not a bill; and the totals for this chat. A number a CLI does not report is left out, never shown as 0. Codex reports no duration, so the script times the call and says so.
- **Account limits.** The model list and each chat show a dim limits line from `scripts/smodel-limits.sh` (see Privacy and safety for what it reads). Data older than 24 hours is marked stale; agy reports no limits.
- **Switch the main chat's model.** The model list shows `main chat: <model>` and a small **→ main** button beside each Claude model; a Claude chat has **Use for main chat**. Either one changes the `/config` Model row, the same change as picking the model there, and a toast says what Claude Code answered (`main chat now on opus`, or its refusal word for word). Codex and agy models cannot run the main chat; their chats say "side chat only".

## Install

When the repository marketplace is available, install it in Claude Code:

```text
/plugin install smodel --marketplace ArielSoothy/smodel
```

For manual use, download the entire folder, replace this example with its absolute location, and launch a new session:

```sh
CLAUDE_CODE_PLUGIN_DIRS="/absolute/path/to/smodel${CLAUDE_CODE_PLUGIN_DIRS:+:$CLAUDE_CODE_PLUGIN_DIRS}" claude
```

## Requirements and current limitations

Use Claude Code 2.1.311 or a compatible newer version. The development engine declarations were generated by 2.1.311; they do not state an exact minimum compatible release. The scripts need `/bin/bash`, Python 3, standard Unix utilities, a writable `HOME`, and access to the current Claude transcript.

Install and authenticate the CLI for each provider you intend to use: `claude` with Anthropic, `codex` with OpenAI, and `agy` with its configured service, such as Google for Gemini. These CLIs are not bundled. The scripts preserve your PATH and add common local/Homebrew locations. Claude resolves from PATH, with `/opt/homebrew/bin/claude` as a fallback. Providers with a missing CLI are hidden and named in a dim diagnostic, such as **codex not installed**. CLI presence does not verify login, quota, model entitlement, or service availability.

Long transcripts and side-chat history are sent through stdin rather than command arguments. Claude and Codex also receive the current message through stdin; agy requires a non-empty `-p` argument containing the neutral consult header and current message, with history supplied through stdin as context. Keep individual agy messages short enough for a command argument. Registry generation and transcript extraction are bundled as `scripts/model-registry.sh` and `scripts/smodel-transcript.py`; no private script or skill is needed. On first open, a missing or invalid registry offers **Refresh models**. A registry older than 24 hours, or with an unreadable timestamp, also offers refresh while retaining usable models. Refresh runs the bundled script and reloads the pane; failures appear in the pane. Merely opening the pane does not replace the registry.

The shared registry stays at `~/.claude/model-registry.json`, compatible with an existing daily updater. Its JSON contains `updated`, `count`, and `providers`; providers contain `id`, `name`, `cli`, `open`, and `models`, with model `id`, `label`, and `effort`. The bundled generator includes installed providers only: Claude aliases, `agy models`, and a fixed Codex list because Codex has no models command. Grok is not listed. Codex defaults are `gpt-6-luna` and `gpt-6.1-sol` at `xhigh`, and `gpt-6-astra` at `high` with a read-only label. Edit the Codex list in `scripts/model-registry.sh` and refresh to change these defaults, or edit the registry directly; later refreshes or another daily updater replace direct registry edits. Aliases and model access depend on your installed CLIs/accounts.

To generate the registry manually, or inspect it without replacing your real registry:

```sh
bash /absolute/path/to/smodel/scripts/model-registry.sh
bash /absolute/path/to/smodel/scripts/model-registry.sh /your/temp/model-registry.json
```

## Privacy and safety

See [PRIVACY.md](PRIVACY.md) for reads, destinations, storage, deletion, and retention. The pane runs locally, but sending a message sends conversation context and your side-chat messages to the chosen provider through its CLI. Claude forks/resumes the original session through the Claude CLI, so its context can include tool content; Codex and agy receive extracted user/assistant text with tool blocks removed. Review the conversation before sending sensitive material. Normal CLI authentication, billing, and provider retention policies apply.

Claude calls disable tools, MCP configuration, and slash commands. Codex uses its read-only sandbox. agy receives a consult-only instruction but has no enforced read-only guarantee in this plugin; a prompt cannot guarantee that it will not change files. The plugin itself saves messages, history, logs, raw answers, session identifiers, and reported statistics under `~/.claude/smodel-chats/<session>/<provider>-<model>/`: `history.md`, `last.log`, `last-answer.md`, `claude-session`, `last-result.json` (the Claude or agy CLI's raw JSON), `last-events.jsonl` (Codex's event stream), `last-stats.json` (the last turn's reported numbers) and `stats.jsonl` (one line per turn). Unsafe path characters in IDs become underscores; normal existing paths stay compatible.

Account limits are optional. The **Show account limits** setting (`showLimits`, default `true`, in Claude Code's `/config` menu) reads `~/.claude/rate-limit-state.json` if present and up to five recent `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` files for reported quota numbers. It does not create a Claude quota hook or make a model call. Set it to `false` to skip these reads and hide the limit lines. Missing data is shown as unavailable, never estimated.

There is no automatic cleanup. Close side chats and wait for running turns to finish, then delete `~/.claude/smodel-chats/<session>/` to remove that session's saved files, or `~/.claude/smodel-chats/` to remove all saved files. Reload/end the Claude Code session to clear the pane's in-memory messages; Claude Code may retain its own plugin/session state. Original transcripts, CLI sessions/authentication, and provider-side records are separate and are not deleted by removing this folder.

## Developing

Type checking requires TypeScript 5.4 or newer. Type-checking and development tests need the generated `.claude-plugin/types/` engine declarations; runtime does not. Those files are ignored alongside dependencies, lockfiles, logs, and macOS metadata.

**Verify before use:** regenerate the engine declarations through Claude Code's plugin scaffold (`claude plugin init <name> --with hooks`; shorthand: `claude plugin init --with hooks`). This CLI's help says scaffolds are created under `~/.claude/skills/<name>/`; choose a temporary name and copy its generated `.claude-plugin/types/` into this checkout. The full regeneration/copy procedure has not been verified here.

```sh
claude plugin test /absolute/path/to/smodel
bunx tsc --noEmit -p /absolute/path/to/smodel
python3 /absolute/path/to/smodel/tests/scripts_test.py
claude plugin validate --profile directory --strict /absolute/path/to/smodel
```

The Python integration checks use isolated temporary files and fake CLIs; they make no authenticated provider calls. Directory validation does not certify marketplace acceptance or replace a provider authentication test.
